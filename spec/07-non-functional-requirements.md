# 7. Non-functional requirements

| ID | Requirement | Verified by |
|---|---|---|
| NFR-1 | Every state-changing call MUST write an `audit_log` row in the same transaction as the change. | `tests/qual32_audit_outbox_test.rs` (ten core mutations over HTTP, one audit row each; a change whose event cannot be written leaves neither the change nor its audit row). Not every route is in the table (QUAL-32) |
| NFR-2 | Every state change MUST write an outbox event in the same transaction; failed publishes MUST be retried and dead-lettered, never dropped. | `tests/qual32_audit_outbox_test.rs` for the scheduling and waiting-list changes. **Not true as written:** 19 modules audit changes without publishing an event (standby, referrals, support flags, transport, receipts and more); which changes publish is an open decision (QUAL-35) |
| NFR-3 | A patient session MUST be able to read only the record named by the `person_id` claim of its verified ID token, never one named in a URL or form. | `ui/tests/unit/access.test.ts`, `ui/tests/e2e/sign-in.spec.ts` |
| NFR-4 | Locale codes MUST be `<language>-<region>`, lowercase, hyphenated; `-001` means "world"; bare two-letter codes MUST NOT be used. | `ui/tests/unit/locale-names.test.ts` |
| NFR-5 | Every locale MUST have every key, no extra keys, and no visible English outside the translation function. | `ui/tests/unit/i18n.test.ts`, `ui/tests/unit/catalogue-coverage.test.ts` |
| NFR-6 | The UI MUST meet WCAG 2.2 AA on every route (axe), including at a 390x844 viewport. | `ui/tests/e2e/a11y.spec.ts`, `ui/tests/e2e/mobile.spec.ts` (automated checks only; no manual audit yet) |
| NFR-7 | The UI MUST send a Content-Security-Policy and the security-header set, with zero CSP violations. | `ui/tests/e2e/security-headers.spec.ts`, `ui/tests/unit/security-headers.test.ts` |
| NFR-8 | Production code MUST contain no `unsafe`. | the compiler (`#![cfg_attr(not(test), forbid(unsafe_code))]`) |
| NFR-9 | Dependencies MUST pass `cargo deny check`; each advisory ignore MUST state why and what removes it. | CI job `deny` |
| NFR-10 | Tests that need PostgreSQL MUST be `#[ignore]`d and MUST fail, not skip, when run without `DATABASE_URL`. | `tests/common/mod.rs`; CI job `rust-db` |
| NFR-11 | A risk score, when one exists, MUST only add support. It MUST NOT remove, reorder away or withhold an offered slot, overbook, or penalise. | `cap10_support_test.rs::no_column_in_the_schema_scores_ranks_penalises_or_suppresses` (a schema guard: any such column fails the build unless it is added, with its reason, to the allow-list in the same change), `::rebooking_options_and_standby_candidates_are_the_same_with_and_without_flags`; and, now that a score exists, `cas5_noshow_test.rs::with_scores_present_rebooking_standby_and_offers_behave_exactly_as_without` and `::test_the_scoring_module_never_writes_to_slots_offers_standby_or_appointments` |
| NFR-12 | The personal-data inventory MUST list every column that holds personal data. | `patient-administration-system-with-rust/tests/personal_data_inventory.rs` |
| NFR-13 | Messages on open channels (SMS, WhatsApp, email) SHOULD carry no clinical detail and SHOULD link to the portal instead. | **Not yet tested** (a convention for template authors) |
| NFR-14 | Secrets MUST come from the environment and MUST NOT be logged. | **Not yet tested** |
| NFR-15 | No message MAY be sent on a channel the patient has opted out of, or outside quiet hours. | `tests/pilot7_consent_test.rs`, `tests/cap13_ladder_test.rs` |

`ui/` abbreviates `patient-administration-system-ui-with-svelte/`.
| NFR-16 | When per-user authentication is on, the audit user id MUST be the verified token subject; a client-supplied `X-User-Id` MUST be discarded, and `X-On-Behalf-Of` MUST be honoured only from an authenticated service. | `tests/user_auth_test.rs`, `tests/token_issuer_test.rs`, `ui/tests/unit/acting-as.test.ts`, `ui/tests/e2e/sign-in.spec.ts` |
| NFR-17 | The REST API MUST be versioned with an `Accept-Version` request header on the one `/api` path, and MUST NOT put a version in the path (no `/api/v1`, `/api/v2`). A request without the header MUST get the current version; an unsupported version MUST be refused with 406. | **Not yet built:** today there is one unversioned `/api`, so nothing breaks; the header is read once a second version exists |
| NFR-18 | Text that comes from a database, a library, a configuration value or another service MUST NOT reach an API or HL7 reply. Those errors are logged in full with a short reference, and the caller gets generic text and the reference. | `error::client_message_tests` (unit), `tests/chaos_api_test.rs` |
| NFR-19 | A background job MUST NOT run on two replicas at the same moment, MUST keep ticking after a run panics, and MUST finish the run it is in when the process is told to stop. | `tests/qual2_jobs_test.rs`, `tests/cap13_ladder_test.rs::two_scans_at_once_send_each_step_once` |
| NFR-20 | Configuration MUST be read through one module, checked when the server starts, and a value that is set but unusable MUST stop the server with a message naming every such variable; it MUST NOT be silently replaced by a default. | `tests/qual6_settings_test.rs`, `config::env::tests` |
| NFR-21 | An audit row, outbox event or in-process event that fails to write after its change is committed MUST be logged with what failed and why. It MUST NOT be discarded silently. (Writing them in the same transaction as the change is NFR-1 and NFR-2.) | `error::log_err_tests`, `tests/qual8_swallowed_errors_test.rs` |
| NFR-22 | Every static SQL statement in the server MUST prepare against the migrated schema. A column read from a raw-SQL row by `col` MUST name the column in its error. | `tests/qual7_sql_prepares_test.rs` |
| NFR-23 | A list endpoint MUST refuse a `limit` outside 1 to 500 with 400 rather than change it, and its response MUST say in `meta` the limit that applied, how many rows it returned, and whether more exist (`truncated`). A work queue MUST NOT stop at a fixed size without saying so. | `paging::tests`, `tests/qual14_paging_test.rs` |
| NFR-24 | Every response MUST carry a request id (the caller's `X-Request-Id`, or one the server makes) that is on every log line of that request; logs MUST NOT hold a path's secrets (a reply-link token or an id is replaced by `{id}`); and an administrator MUST be able to read, without identifiers, requests by status class, each background job's runs and last success, the outbox backlog and its age, dead letters and open call tasks (`GET /api/admin/metrics`). | `tests/qual16_observability_test.rs`, `observability::request_tests`, `metrics::tests` |
| NFR-25 | When the audit row for a write cannot be written, the write MUST be refused (the request fails and the change is not kept); a write MUST NOT succeed with its audit row missing or only logged. This applies to every state-changing call, and it tightens NFR-21, which allows an audit row to be logged-and-lost only where it cannot share the change's transaction. The same holds for a read of one patient's record (FR-190). | Met for the reads of FR-190, the routes in `tests/qual32_audit_outbox_test.rs`, and (QUAL-37, 2026-10-24) the consent, coverage, encounter, letter-template, facility, ward, room and bed writes, HL7 v2 S13 and S14, and sending a message, whose audit row and event are written in the change's transaction (a message: the attempt row is written before it is sent, and nothing is sent if that fails). `tests/qual37_audit_refuses_test.rs` makes the audit insert fail for one user and shows five of those routes refused with no change, and a message not sent. **Where it cannot hold:** the two rows that record a send's *outcome* (`send_..._ok`, `send_..._failed`) are written after the send, which cannot be undone; a failure there is logged (NFR-21) and the attempt row already records the send. **Not shown:** a test for each remaining route (coverage, encounter set-status, other letter routes, S13, S14, ward, room, bed) |
