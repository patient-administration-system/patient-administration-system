The audit is QUAL-40 in `tasks.md`; its first pass is `governance/national-assumptions.md` (13 findings, all open), and `tests/qual40_national_assumptions_test.rs` stops a file gaining a national name (a text count, not proof of absence) |
| NFR-27 | Concurrent edits to one record MUST be handled by optimistic concurrency, not by a lock held while a person looks at a screen. A database row lock (`SELECT ... FOR UPDATE`) is allowed only inside one transaction, never across requests. A route that does not yet check a version MUST say so in `spec/09-api-surface.md`. | `tests/ofh1_concurrency_test.rs`, `tests/ofh10_versions_test.rs` (FR-195, FR-199). **Not yet built** for the in-place edits that `spec/09-api-surface.md` lists as last-writer-wins (tasks.md OFH-11); inbound HL7 v2 and FHIR writes are accepted as `*` by decision; the staff screens do not write yet, so none sends the header. |

| NFR-30 | The UI MUST ship a **light and a dark theme** for each audience (staff and patient), and each of the four MUST pass what NFR-6 asks of the UI on every route: WCAG 2.2 AA under axe, colour contrast included, at the desktop and the 390x844 viewport. **The UI MUST use the browser's light or dark setting** (`prefers-color-scheme`) to pick the light or the dark theme, on the first page and with no flash of the other, and MUST follow it when it changes, until the person chooses a theme themselves. **Every page MUST offer a theme control** with three choices, **Follow this device**, **Light** and **Dark** (Follow this device is the default and hands the choice back to the browser), **kept in a cookie** the server reads, so the first paint is already in the chosen theme; the choice outlives signing out, and is kept per browser, not per account. A person MAY choose **another theme that does not pass** (a deployment's or an organisation's own, a softer low-contrast one, a colour-vision or low-light one), because the choice is theirs: it MUST apply only to that person, MUST be kept for them, MUST be undone in one step from every page back to a passing theme, and MUST NOT be anyone else's default. A theme a deployment makes the default for everyone is not a person's choice: it MUST pass as the shipped themes do. | **Built** (tasks.md UI-4), completed 2026-11-19: the staff and patient themes have dark variants (`ui/static/assets/themes/`, every text and fill pair 7:1 or more); the header's `@lilydesignsystem/svelte-theme-picker` offers Follow this device, Light and Dark, keeps a choice per browser in the `theme` cookie and local storage, and the server reads it before the first paint. No optional additional theme is installed; if a deployment adds one, the conditional rules in this requirement apply. Choosing a theme needs JavaScript; following the device does not. |

| NFR-32 | **Every outbox delivery MUST end in one of three classes.** *Accepted* (2xx): done. *Rejected* (a 4xx that cannot succeed on retry): dead-lettered at once, with the status. *Deferred* (408, 429, 5xx, a network error): tried again after a delay that starts at 5 seconds, doubles, honours `Retry-After`, caps at 15 minutes and resets on success, until the retry budget dead-letters it. An event MUST NOT be delivered while an earlier event for the same aggregate is undelivered, and a dead letter MUST hold its aggregate until a named person replays or skips it (`POST /api/admin/outbox/dead-letters/{id}/skip`, audited). | `streaming::dispatcher`, `streaming::webhook::classify`, `OutboxRepository::fetch_due`, migration 66; `tests/hub4_outbox_classes_test.rs` (HUB-4, 2026-11-17).
